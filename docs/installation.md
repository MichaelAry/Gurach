# Установка Gurach

Установщик разворачивает клиент, API и MongoDB с replica set в Docker Compose. В образ API входят инструменты обработки аудио. На пустой базе установщик применяет миграции и создаёт администратора `gurach`. Для успешного завершения должны пройти проверки готовности API и главной страницы.

## Что понадобится

- Windows 11 x64, сборка 22631 или новее, с доступной аппаратной виртуализацией для WSL 2. При первой установке Windows может запросить подтверждение UAC, перезагрузку и принятие условий Docker Desktop. [Требования Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/)
- Ubuntu 24.04 x64 с systemd. Для установки Docker Engine и Compose нужны права root или доступ через `sudo`.
- Интернет для загрузки системных пакетов и образов. Для установки из архива релиза заранее ставить Git, Node.js и npm не нужно.

## Первый запуск

### Windows

1. Скачайте `Gurach-installer.zip` из [релизов Gurach](https://github.com/MichaelAry/Gurach/releases) и полностью распакуйте его.
2. Запустите `install.cmd` из распакованной папки. Подтвердите включение компонентов Windows, если появится диалог UAC. Если установщик попросит перезагрузку, перезагрузитесь и войдите в ту же учётную запись. Установка продолжится автоматически после входа.
3. Если Docker Desktop откроет окно с условиями использования, подтвердите их в этом окне. Когда контейнеры будут готовы, установщик откроет Gurach в браузере.

### Ubuntu

Скачайте `Gurach-installer.tar.gz` со страницы релиза и выполните в каталоге загрузки:

```sh
mkdir -p gurach-installer
tar -xzf Gurach-installer.tar.gz -C gurach-installer
cd gurach-installer
sh install.sh
```

Если Docker отсутствует, установщик настроит репозиторий Docker для Ubuntu, установит нужные пакеты и включит службу.

### Запуск из исходников

В полной копии репозитория запускайте `install.cmd` на Windows или `sh install.sh` на Ubuntu. Установщик соберёт образы из исходников. Архив релиза загружает готовые образы, привязанные к конкретным digest.

## Вход и файлы установки

| Что | Где |
| --- | --- |
| Приложение | `http://localhost:3000` |
| Готовность API | `http://localhost:5000/health/ready` |
| Логин администратора | `gurach` |
| Начальный пароль | Строка `GURACH_INITIAL_PASSWORD` в `install.env` |
| Рабочая папка Windows | `%LOCALAPPDATA%\Gurach` |
| Рабочая папка Ubuntu | `~/.local/share/gurach` текущего пользователя |

В `install.env` хранятся также учётные данные MongoDB и секреты приложения. Храните файл как пароль. MongoDB доступна внутри сети Docker. Порты интерфейса и API привязаны к локальному интерфейсу компьютера. База и загруженная музыка хранятся в отдельных именованных томах Docker.

## Порты, остановка и повторный запуск

Если порт 3000 или 5000 занят, откройте `install.env` в рабочей папке, добавьте нужные строки со свободными портами и запустите установщик повторно:

```dotenv
GURACH_WEB_PORT=3300
GURACH_API_PORT=5500
```

Открывайте адрес, который выводит установщик. В примере это `http://localhost:3300`, а готовность API проверяется на `http://localhost:5500/health/ready`.

Для остановки на Windows нажмите **Stop** у проекта `gurach` в Docker Desktop. На Ubuntu выполните из любой директории:

```sh
gurach_dir="$HOME/.local/share/gurach"
sudo docker compose --env-file "$gurach_dir/images.env" \
    --env-file "$gurach_dir/install.env" \
    -f "$gurach_dir/runtime/deploy/compose.yml" stop
```

Если текущему пользователю доступен Docker, `sudo` можно опустить. Для запуска снова откройте установщик. При обычной загрузке Ubuntu Docker поднимает контейнеры, а на Windows Docker Desktop запускается после входа пользователя.

Повторная установка той же версии сохраняет секреты, базу и музыку. Если новая версия требует миграций на базе с данными, используйте [руководство по миграциям](execution/migrations.md).

## Диагностика

- Если Windows не может запустить WSL 2, проверьте виртуализацию в UEFI или вложенную виртуализацию в виртуальной машине. Если Docker Desktop запущен, убедитесь, что он использует Linux-контейнеры.
- После сбоя на Windows откройте `%LOCALAPPDATA%\Gurach\install.log`. На Ubuntu ошибки видны в терминале. При сбое запуска сервисов установщик также сохраняет их последние сообщения в `~/.local/share/gurach/install-error.log`.
- При обрыве загрузки повторно запустите установщик. Для проверки после запуска откройте домашнюю страницу Gurach и endpoint готовности API. Успешный ответ API содержит `{"status":"ok"}`.

## Выпуск архива

При пуше тега `v*` GitHub Actions собирает образы, проверяет запуск, публикует образы в GHCR и прикладывает ZIP, TAR.GZ и файл контрольных сумм к GitHub Release. При первом выпуске откройте анонимное чтение обоих пакетов GHCR и при необходимости повторите workflow.
