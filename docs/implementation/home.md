# Главная страница

Три основных блока: «Продолжить прослушивание», «От друзей», «Новые треки».
Гость видит продолжение из PlayerProvider и единственный список новинок;
пустая лента друзей ему не показывается. Быстрые ссылки и QueuePanel сохранены.
Дополнительные блоки популярного, статистики и списка друзей убраны с главной.
Продолжение использует существующую сохранённую позицию плеера из задачи 16.

## Открытие музыки

`GET /home/discovery` — личный ответ с `private, no-store`, защищённый SessionGuard.
Подбор внутри «Продолжить» берёт исполнителей из последних 30 прослушиваний
(по listenedAt, затем ID) и 30 избранных. Недоступные треки не дают сигналов.
Кандидаты выбираются из всего активного каталога с непустым аудио: по
нормализованному исполнителю (для старых строк также по точному artist),
кроме треков из этих двух выборок. До шести результатов, свежие ID первыми.
Это подбор по исполнителям, а не модель похожести или полный анализ истории.
Чужие прослушивания и избранное не используются.

DTO `HomeDiscoveryResponse.basis` различает `artists`, `no-signal` и `no-matches`.
Два последних состояния возвращают пустой список с честным объяснением и
ссылкой на каталог/существующие новинки. Копия новинок под видом рекомендаций
не выводится. Изменения избранного и подтверждённые прослушивания обновляют
подбор через существующие FavoritesProvider.revision и useListenRevision.
`useHomeBlock` включает аккаунт, путь и ревизию в ключ, сразу скрывает устаревший
ответ и отменяет запрос при смене ключа. Неподтверждённая сессия запрещает личный
запрос и применение его ответа. При возврате фокуса ViewerProvider перепроверяет
сессию; лента друзей перемонтируется и перечитывает отношения.

## Списки и курсоры

- `/home/releases`: существующая публичная страница последних 20 доступных
  треков. Порядок по убыванию ObjectId сохранён; курсор v2 привязан к виду списка.
- `/home/popular`: прежний публичный API топа за 7 суток остаётся совместимым;
  отдельного блока на главной нет. Гостевые прослушивания не входят в расчёт.
- `/home/activity`: публикации, комментарии и оценки принятых друзей без
  блокировок; отключённые пользователи исключены. Каждая страница заново читает
  отношения. Агрегация объединяет источники и проверяет активный трек с непустым
  аудио до ограничения в 21 запись (20 плюс признак продолжения). Удалённые,
  карантинные комментарии и недоступные треки не занимают места на странице.
  Нет запросов на каждое событие.

События сортируются по реальному времени убывания: publishedAt для новых
публикаций, createdAt для комментариев. Для старых строк без времени используется
время ObjectId. publishedAt записывается при публикации, редактирование метаданных
его не меняет. Стабильный порядок при равном времени: ID, затем тип источника
(upload/comment), оба по убыванию. Курсор v3 содержит все три значения и fingerprint
вида списка с ID аккаунта. Курсоры другого аккаунта/списка, старого формата или с
неверной датой возвращают 400. Это позиция, не разрешение на чтение: отношения и
доступность всегда проверяются снова. Курсор новинок не принимается в ленте и наоборот.

Клиент за один проход Map группирует повторы автора/действия/трека за день UTC
в пределах загруженных страниц, сохраняя порядок первого (новейшего) события.
Объединение страниц также линейное. Комментарии открываются по существующим
ссылкам `/tracks/:id#comment-:id` с загрузкой целевого комментария из задачи 10.

## Кэш и контракт

Личные ответы API и BFF остаются `private, no-store`. Общий кэш хранит только
публичные данные releases/popular в Next `use cache`: revalidate 15 секунд,
expire 30 секунд, stale 0. Параметры списка входят в ключ. Общий тег `tracks`
инвалидируется через `invalidateTrackCaches` из задачи 15 при публикации, правке
и удалении, включая durable cache events и повторы доставки. HTTP-ответы BFF
имеют no-store: браузер/CDN не обходят эту инвалидацию. Ошибки не кэшируются.

DTO документированы в серверном OpenAPI и перегенерированы в клиентские типы.
Fixture поддерживает discovery и его явные причины fallback. Новые тесты и
зависимости не добавлены. Для выборки сигнала HomeService создаёт индекс
`{ userId: 1, listenedAt: -1, _id: -1 }`; индексы авторов сохранены. Агрегация смешанных событий сортирует вычисленное время после фильтрации.
