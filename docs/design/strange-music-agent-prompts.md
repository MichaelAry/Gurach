# Готовые промпты для агентов: лаборатория странной музыки Gurach

Актуальные статусы и правила выбора следующей идеи находятся в разделе «Статусы реализации» документа концепций; этот файл хранит задания. Концепции: [strange-music-lab.md](strange-music-lab.md). Порядок — от простого первого варианта к сложному, номера идей исходные.

Каждый блок ниже — самостоятельный промпт, его можно скопировать целиком в новую сессию агента. Промпт явно выбирает эксперимент, поэтому не означает запрос следующей задачи из общей очереди улучшений. Все 13 заданий выполняются отдельно. По запросу «реализуй новую идею» агент сам выбирает ID по очереди в документе концепций и использует соответствующий блок; копировать промпт вручную не требуется. Поздние промпты требуют проверки фактической готовности зависимостей, а не предположения, что предыдущие уже сделаны.

```text
Перед изменениями прочитай корневой и применимые локальные AGENTS.md, README.md, раздел этой идеи в docs/design/strange-music-lab.md и актуальный код соответствующих функций. Проверь git status, сохрани чужие изменения. Используй существующие архитектуру, плеер, очередь, модели доступа, фоновые задачи и механизмы сохранения; пути и API выясни из кода. Задание 04: Износ от любви

Реализуй личную «затёртую копию» обложки: музыка приобретает видимые следы реального прослушивания. Нужны три степени износа, стабильный рисунок для пары слушатель–трек, переключатель оригинала и личной копии, сброс износа. Для гостя выбери понятное локальное хранение; данные аккаунтов должны быть разделены.

Сначала исследуй источник событий плеера и существующий учёт истории. Зафиксируй правило засчитывания прослушивания: одно завершение одной сессии даёт одно событие; пауза, перемотка к концу, повторный рендер и дублированный обработчик не должны искусственно умножать счётчик. Если существующая история использует другое обоснованное правило, переиспользуй его и опиши. После сброса старые события не должны сразу возвращать прежний износ.

Сделай визуальный слой из заломов, колец и потёртостей, воспроизводимый по стабильному зерну. Эффект должен выглядеть как индивидуальная биография предмета. Исходный файл не меняется. Встрой слой в существующее отображение обложки, не заставляя весь каталог обновляться при каждом изменении позиции. Обложка без изображения тоже должна иметь осмысленное состояние. В панели «моя копия» покажи реальную степень износа без выдуманной истории.

Проверь накопление, смену аккаунта, перезагрузку, сброс, повторный запуск и уменьшение движения. Приёмка: два реально разных состояния слушания дают различимый износ; один и тот же сохранённый случай после перезагрузки выглядит одинаково; оригинал доступен одним действием.

Проверки и завершение:

- Выполни подходящие существующие проверки типов, локализаций, линтинга и затронутых тестов. Для новых контрактов проверь авторизацию и ограничения; при изменении API обнови предусмотренные проектом схему и клиентские типы.
- Добавь тесты значимой новой логики и один сквозной сценарий основного пути, если для него существует подходящая инфраструктура. Не создавай тесты, которые лишь повторяют разметку. Визуальную часть осмотри в браузере; скриншоты или их пути приложи к отчёту, если доступны. Недоступную проверку явно назови.
- Проверь, что воспроизведение, очередь и навигация не получили регрессий в затронутых сценариях. Отметь ограничения первой версии и отдельно запиши расширения; не выдавай их за выполненное.
- Обнови запись этой идеи в docs/design/strange-music-lab.md: статус, решения, файлы, команды и результаты проверок, ограничения, следующий шаг. Статус done допустим только при выполнении приёмки; иначе сохрани точку продолжения. Статус обновляй в таблице «Статусы реализации», доказательства и точку продолжения — в разделе «Журнал реализации»; не создавай дублирующую таблицу статусов в этом файле.
- В финале сообщи, что пользователь теперь может сделать, как проверено и что осталось. Коммит и публикацию выполняй только по явным указаниям пользователя.
```

```text
Задание 13: Паразит интерфейса

Посели внутри Gurach небольшое существо, которое реагирует на музыку и оставляет наблюдаемые следы привычек слушателя. Реализуй пять состояний: покой, исследование нового исполнителя, гнездо повторов, сон при пустой очереди, найденный предмет. Персонаж выполнен простыми SVG/CSS-формами с выразительным силуэтом; уникальность достигается поведением и пластикой.

Опиши таблицу событий и переходов. Подключись к семантическим событиям плеера и коллекции, а не к частым обновлениям времени. Повтор должен означать реальное повторное воспроизведение; переходы получают задержку и ограничение частоты. Существо строит декоративное гнездо вокруг безопасной зоны обложки, сворачивается в пустой очереди и по явному нажатию предлагает забытый доступный трек. Если подходящих реальных данных нет, состояние находки недоступно: вымышленные рекомендации не нужны.

Выдели фиксированные места проживания вне кнопок, текста и фокуса. Украшения не перехватывают указатель, интерактивное существо имеет доступное имя. Добавь отключение, сохранение предпочтения и спокойные статические позы при reduced motion. Храни только небольшой объём состояния отдельно по слушателям. Измени внешний вид гнезда после нескольких повторов так, чтобы реакцию было понятно наблюдать без объясняющего диалога.

Проверь переходы чистой логикой с управляемым временем, отсутствие лавины событий, отключение, уход со страницы и смену аккаунта. В браузере проверь мобильную раскладку и основные кнопки. Приёмка: характер читается минимум в трёх последовательных действиях, звук и очередь меняются исключительно по действиям пользователя.
```
